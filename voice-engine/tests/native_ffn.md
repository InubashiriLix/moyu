# 原生 FFN 回归记录（v0.4.4）

## 故障原因

用户在 RTX 4060 / CUDA / balanced / Q5_K 上，每朗读几句就出现 3–20 秒“缓冲中”。此前仅用 F16 验证连续播放，未覆盖用户实际使用的量化模型。

固定版本的 Talker 与 CodePredictor 在五处 FFN down projection 中，先调用 `ggml_cast(weight, F32)`，再矩阵乘法。CUDA 的 `GGML_OP_CPY` 不支持 Q5_K→F32，因此调度器把整块矩阵的转换放到 CPU，逐 token 重复执行；残差码本还会重复此过程。主后端显示 CUDA0，不能说明每个算子都运行在 GPU。

用同一库、相同输入、Serena、seed=42、balanced、关闭缓存，在 RTX 5060 8 GB 上复现：短句 2.14 秒音频需要 12.87 秒生成；长句 CodePredictor/Talker 合计约 136 秒。12 秒量级的短句生成在热运行中仍能复现，排除了仅冷启动问题。权重元数据确认 embedding 为 F16，排除了量化 embedding 的 GET_ROWS 假设。

## 改动与精度约束

量化权重直接交给原生矩阵乘法，不再整矩阵反量化到 F32。CPU 和 Vulkan 同样使用各自支持的量化乘法。CPU/Vulkan 的浮点路径保持原样。

CUDA F16 的单 token FFN 直接读取 F16 权重，显式要求 F32 累加；多 token 预填充保留原 F32 路径。曾尝试同时优化预填充，但数值测试出现差异，因此未采用。测试覆盖 2048/6144 输入维度、单 token 和 8 token：CUDA F16 对照 F32 权重乘法的相对 L2 误差在该确定性测试中为 0；Q5_K 原生乘法对照反量化 F32 的相对误差为 0.22%–0.72%（包含原生量化乘法中的激活量化）。这不能证明所有输入的输出逐位相同，也不能替代音质主观验收。

权重文件未修改。数学内核改变可能通过采样改变生成长度，因此性能按生成音频时长归一化，不能仅比较同一文本的总耗时。缓存 key 的生成配置版本同步升级，避免旧缓存掩盖回归。

## 测量

本机 Arch Linux、i5-14600KF、RTX 5060 8 GB。不能视为 RTX 4060 实机验收。

| 路径 | 音频秒数 | 合成耗时 | RTF（越低越好） |
|---|---:|---:|---:|
| 旧 Q5_K，冷启动的两段混合输入 | 27.15 | 155.11 秒 | 5.71 |
| 修正 Q5_K，同文本热运行 | 30.03 | 13.92 秒 | 0.46 |
| 原 F16，同文本热运行 | 27.47 | 19.28 秒 | 0.70 |
| 优化 F16，同文本热运行 | 29.47 | 15.58 秒 | 0.53 |

模型加载和播放排空时间不计入表中的合成耗时。Q5_K 修正前的完整播放约 184 秒，其中一次再缓冲约 140 秒；修正后短、长段的冷/热混合测试均无再缓冲、无欠载样本。

连续测试重复 12 个长短段落，用真实音频设备回调消费，输出定向到专用 PulseAudio null sink，关闭片段缓存并保存 WAV。Q5_K 音频 180.20 秒、F16 音频 176.84 秒，均为零再缓冲、零欠载样本。以 20 ms 窗口和约 −74 dB 阈值检查保存音频，最长低音量区间分别为 0.10 秒、0.72 秒，没有数秒空白；这只是静音检查，不能替代发音与音色验收。

完整 AppImage 在独立的 niri + Wayland + DMS 会话中，实际完成 CUDA r1→r2 升级（732,698,971 字节从本地校验复用，947,152 字节下载）、Q5_K/balanced/Serena 的 gr 播放、准备中及播放中 gp 暂停/恢复、无再缓冲至章节结束、缓存重播、gs 停止、非零 PCM 接收和托盘退出。Vulkan 的 Q5_K 两段真实播放同样无再缓冲；纯 CPU Q5_K 的短句合成也通过，但低于实时速度。

## 复测入口

`ctest --test-dir build-cpu --output-on-failure` 包含纯 CPU 的量化数值与计算图检查；CUDA 构建下 `ctest --test-dir build-cuda -R '^ffn$' -V` 额外在 GPU 上验证 F16/Q5_K。图检查确保量化权重和 CUDA 单 token F16 权重没有被先 cast。

用 CLI 对同一文本、关闭缓存分别测试 `--model qwen3-tts-1.7b-customvoice-f16` 和 `--model qwen3-tts-1.7b-customvoice-q5_k`，传入 `--backend cuda --power-mode balanced --speaker Serena --seed 42 --no-cache --no-play --output output.wav --metrics metrics.json`，通过 `NV_PROFILE=1` 读取细分耗时。播放连续性必须另行启用播放，并检查欠载样本数和界面“缓冲中”状态，不能以无播放的吞吐测试代替。

## 分发

修正在独立下载的工作程序中，仅换 AppImage 不会修复已安装的 r1 CUDA 工作程序。清单升级为 `74422b-cuda13-abi1-r2`；设置提供“更新组件”，逐块校验并复制内容相同的旧文件，只下载约 925 KiB 的新工作程序。旧安装不变，不使用硬链接。损坏的旧文件不能复用，将重新下载。三个新工作程序渠道均以实际完整下载校验 SHA-256。
